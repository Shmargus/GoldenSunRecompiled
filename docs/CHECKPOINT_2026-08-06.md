## Performance

Measured headless, 5,400 campaign frames, `-O3 -DNDEBUG`, this machine.

| build | track | fps | vs hardware |
|---|---|---|---|
| no LTO | campaign | 42.5 | 0.71x — **slower than a GBA** |
| **LTO** | campaign | **64.8** | **1.09x** |
| LTO | no input | 56.5 | 0.95x |
| LTO + `-march=native` | campaign | 65.6 | 1.10x — **rejected, see below** |

Throughput is scene-dependent: the same binary runs the `campaign` route at
1.09x and the no-input attract path at 0.95x. "Roughly realtime" is the honest
description, not "comfortably above it". A windowed run adds presentation and
audio cost on top of these headless figures.

`-march=native` was measured, not assumed, and **rejected**: +1.2% is inside
run-to-run noise and does not justify tying the binary to one CPU. The flag was
reverted and the verified generic binary restored rather than left in place.

LTO is verified behaviour-preserving rather than assumed. Every semantic
fingerprint is byte-identical across the two binaries:

```
steps=20362  cycles=1042707251  final_pc=0x000001b4
unmapped=0   io_unhandled=0     ppu_vcount=49  ppu_frames=5400
pal_nonzero=931/1024  vram_nonzero=58877/98304  oam_nonzero=542/1024
```

Cost: ~25 minute link, 75.4 MB binary. GCC runs LTO partitions serially by
default, so most of that is one core; `-flto=N` should be investigated for the
development loop.

### The cost of static coverage is real and should be tracked

An earlier session measured 1.50x realtime with LTO at a corpus of ~24,480
functions. The corpus is now 32,760 functions (+34%) and the same build
configuration yields 1.09x. Chasing strict-static coverage has a measurable
throughput cost — most likely instruction-cache pressure from a larger dispatch
surface. This is a genuine trade-off, not a regression to fix blindly, but it
should be measured each time the corpus grows substantially rather than
discovered later.

## Presentation fix (upstream `gbarecomp`)

The F1 video tab's "Integer scaling" checkbox was **inert**. `integer_scale` was
applied through `SDL_RenderSetIntegerScale`, which only affects the
`SDL_RenderSetLogicalSize` path, while frames are actually presented via
`compute_presentation_layout` + `SDL_RenderCopy` into an explicit destination
rect — bypassing it entirely. The checkbox defaulted ON and did nothing.

The layout function maximised fill at the logical aspect in reduced-ratio units,
which lands on a whole multiple of 240x160 only rarely:

| window | destination | scale | source pixel widths |
|---|---|---|---|
| 800x600 | 798x532 | 3.325x | 3 and 4 |
| 1000x700 | 999x666 | 4.162x | 4 and 5 |
| 1920x1080 | 1620x1080 | 6.750x | 6 and 7 |

Under nearest-neighbour that is uneven pixel duplication — the visible wobble.

Fixed by giving `compute_presentation_layout` a `ScalingMode`
(`IntegerLetterbox` default, `AspectFill` = old behaviour, `Stretch`) and wiring
the user preference into the present path. `presentation_layout_tests` asserts
the property that matters — uniform source-pixel width across a sweep of real
window sizes — not just fixed numbers. Upstream suite 17/17.

Not visually confirmed on screen; the windowed path did not engage in the
automation environment. Worth a human eyeball.

## What this does NOT claim

- **FULLY_STATIC is frame- and track-bounded.** `campaign` is ONE deterministic
  route. Another route will find its own gaps. 10,800 frames of that same route
  is not static.
- **No oracle comparison has been run against this state.** The GS-010 `DISPSTAT`
  cycle-drift finding has not been retested.
- `Func_155d0` is registered pre-emptively and **has never verified in any run**.
  It is inert until it does.
- The 95.9% BG-mode-2 measurement covers 400 frames of boot/title/file-select,
  not battles or the overworld.
- Performance numbers are from one machine, headless, with no window, audio
  device or pacing. A windowed run has additional cost.

## Reproduce

```powershell
# static coverage
python tools/build_main_toml.py --rom <ROM> --elf <goldensun.elf> `
  --corpus local/symbols/main-symbols.json `
  --data-exceptions config/usa/main-data-exceptions.json `
  --output config/usa/main.toml `
  --disassembly-revision 84a80693003439acdbb78dd84538b0532461ad4b
<gba_recompile> --rom <ROM> --config config/usa/main.toml `
  --out local/gs011/main --max-functions 40000

# build (LTO is what buys 1.09x; omit for a fast development loop)
cmake -DCMAKE_INTERPROCEDURAL_OPTIMIZATION=ON .
cmake --build . --target GoldenSunRecomp -j 8

# verify
$env:GBARECOMP_STRICT_STATIC='1'; $env:GBARECOMP_DEMO_INPUT='campaign'
.\GoldenSunRecomp.exe --bios <BIOS> --rom <ROM> --no-window --frames 5400
```

The no-input track requires `GBARECOMP_DEMO_INPUT` to be genuinely **unset** —
an empty value ENABLES a demo track and silently invalidates the comparison.
